# 事件风暴 Event Storming
Lab3 Sprint1｜A角色主执笔，全员参与研讨
> 本文件为团队数字白板整理输出，基于全员头脑风暴结果；
> 包含：参与者、领域事件、命令、聚合、不变式、限界上下文、上下文映射、统一语言术语表。

## 参与角色（黄色卡片）
访客、注册普通用户、提问者、回答者、教师、系统定时任务

## 系统限界上下文划分
1. **Identity 身份上下文**：账号注册、个人资料、选课审批、身份权限管理
2. **Q&A 问答上下文**：问题发布、编辑、回答提交、投票、答案采纳，平台核心问答业务
3. **Reputation 声誉上下文**：根据用户问答行为自动计算、维护用户声誉分值
4. **Discovery 发现上下文**：标签、检索、问题索引，实现内容查找过滤

## 聚合识别清单（紫色聚合卡片）
| 聚合根实体 | 归属限界上下文 | 关键业务不变式 |
| ---- | ---- | ---- |
| UserAccount | Identity | 用户账号唯一；邮箱不可重复注册；仅本人可修改个人资料；教师才拥有选课审批权限 |
| Question | Q&A | 问题标题、正文不能为空；仅提问者可以编辑问题；问题删除后关联回答一并失效 |
| Answer | Q&A | 回答必须绑定有效存在的Question；仅回答作者可编辑回答；一个问题可以拥有多条回答 |
| UserReputation | Reputation | 声誉分数≥0；分数只能由系统业务行为自动计算，用户无法直接手动修改分数 |
| QuestionIndex | Discovery | 索引数据必须和Q&A上下文的问题数据保持最终一致性 |

## 上下文映射 Context Map
1. Identity ←→ Q&A / Reputation / Discovery：客户‑供应商模式，其他上下文只读查询用户基础身份信息，不修改Identity内部数据。
2. Q&A → Reputation：发布‑订阅模式，Q&A产生领域事件，Reputation监听事件自动更新声誉。
3. Discovery ← Q&A：客户供应商，Discovery读取Q&A数据构建检索索引，单向数据同步。

## 统一语言术语表 v1.0
| 中文术语 | English | 业务定义 |
| ---- | ---- | ---- |
| 问题 | Question | 用户发布的咨询内容，包含标题、正文、标签 |
| 回答 | Answer | 用户针对问题给出回复内容，隶属于某一个问题 |
| 声誉 | Reputation | 衡量用户在平台贡献的积分，由提问、回答、回答被采纳获得 |
| 限界上下文 | Bounded Context | 按业务能力划分的独立业务边界 |
| 领域事件 | Domain Event | 领域内已经真实发生的业务事实，使用过去时命名 |
| 命令 | Command | 用户或系统发起的业务动作请求，不一定执行成功 |
| 聚合根 | Aggregate Root | 聚合对外唯一访问入口，保护聚合内部实体一致性 |
| 不变式 | Invariant | 业务必须永远满足的业务约束条件 |
