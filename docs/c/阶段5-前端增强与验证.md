## 3. 完成功能

### 3.1 加载、空状态、错误与并发请求

- 问题列表、排行榜、通知列表增加明确的加载、空数据和错误状态，并提供重试按钮。
- 问题搜索和排行榜切换使用递增请求编号，只接收最后一次请求的结果，避免慢的旧请求覆盖新筛选结果。
- 通知页面保留 30 秒轮询，并在卸载时清除定时器、使在途结果失效。
- 提问、回答、评论、悬赏、单条已读和全部已读在提交期间禁用重复操作。
- 提问、回答、评论和悬赏失败时保留用户输入并展示后端错误。

### 3.2 Markdown 实时预览

- 提问正文和回答编辑区增加实时预览。
- 使用维护中的最小依赖 `react-markdown`。
- 显式设置 `skipHtml`，不渲染原始 HTML；未引入 `rehype-raw`，未使用未经净化的
  `dangerouslySetInnerHTML` 生成预览。
- 问题和回答的既有 `bodyHtml` 展示逻辑未改动；它仍依赖项目原约定的后端 CommonMark + OWASP Sanitizer 净化。

### 3.3 悬赏对话框

- 用原生 `<dialog>` 替换 `prompt()`。
- 根据 `BountyController.BountyRequest` 校验积分 `10–500`、期限 `1–14` 天，没有增加自定义业务规则。
- 支持取消、提交中状态和后端错误提示；失败不清空输入。
- 对话框打开后聚焦积分输入，Escape 可关闭，关闭后焦点恢复到“发起悬赏”按钮。

### 3.4 通知交互

- 接入既有 `POST /api/v1/notifications/{id}/read`，支持单条标记已读。
- 单条或全部标记成功后立即更新列表，并触发顶部未读数量刷新。
- 顶部仍每 30 秒轮询未读数；卸载时清理定时器和事件监听器，轮询失败保留上次计数并显示状态提示。
- 未引入 SSE，也没有改动认证或权限模型。

### 3.5 移动端与键盘操作

- 增加 640 px 小屏断点：顶部导航换行、筛选控件全宽、问题统计横排、文章和通知布局收缩。
- 为按钮、链接和表单控件增加可见的键盘焦点样式。
- 对话框支持 Tab 键的浏览器原生焦点约束、Escape 关闭和焦点恢复。

## 4. 修改后验证

### 4.1 静态验证

```text
npm ci --no-audit --no-fund
npm run typecheck
npm run build
```

提交前使用锁文件完成干净安装，三条命令均通过。生产构建转换 207 个模块，产物 JS 303.17 kB
（gzip 96.98 kB）、CSS 6.38 kB（gzip 1.87 kB）。体积增长主要来自 Markdown 解析依赖。

项目没有预置 Vitest、Jest、React Testing Library 或其他前端测试脚本，因此未为本阶段临时搭建另一套测试框架，也没有声称运行了自动化交互测试。

### 4.2 浏览器交互验证（隔离 mock）

使用仓库外的临时 Node HTTP mock 和本地 Vite 服务验证；mock 文件没有放入仓库，未向生产代码加入伪数据或假成功。

实际确认：

- 问题列表成功数据和“无结果”空状态均正确显示。
- Markdown 标题、行内代码、加粗可实时预览；输入的 `<script>` 原始 HTML 未渲染或执行。
- 悬赏对话框默认显示 50 积分、7 天，初始焦点在积分框；Escape 关闭后焦点回到触发按钮。
- 单条通知标为已读后，操作按钮消失，顶部未读数量从 1 更新为 0，全部已读按钮相应禁用。
- 停止 mock 后访问排行榜，页面显示“请求失败”和“重试”按钮，而不是错误地显示空榜。
- 当前浏览器没有提供 viewport 覆盖能力，因此没有完成真实窄视口截图；小屏部分仅完成 CSS 规则核对，需在后续浏览器设备模拟或实体手机上补验。
